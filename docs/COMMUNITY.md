# Open community and stewardship — initial proposal

This is a proposal for a welcoming, small open project; not a declaration that a legal foundation, staffed team, or formal community governance already exists.

## Community purpose

Enable chess enthusiasts, historians, composers, educators, designers and engineers to create, verify, share and improve playable chess literature. The community's value lies in **authored work, historical care, and mutual agency**, not in producing free content for a closed growth platform.

## Contribution paths

- Fix factual attribution, date, source or game record.
- Review a composition for solution soundness and accurate theme explanation.
- Propose or refine a narrative, translation, media credit, or accessibility improvement.
- Improve the reader, board, import, documentation or verification tests.
- Suggest an artifact or collection, with a source and reason it is interesting.

Contributor roles may overlap. Community members should see how their feedback changes decisions and be credited for original work.

## Proposed lightweight decisions

- **Maintainer/steward:** Makes final merge decisions initially, explains rejections and is accountable for mission integrity.
- **Editors/reviewers:** Have substantive input on provenance, narrative and chess verification; a technical merge is not a factual endorsement.
- **Authors:** Retain explicit authorship attribution; content licensing must be agreed before inclusion.
- **Contributors:** Can propose, review, challenge claims and request corrections. Disagreement should be documented rather than erased.
- **Expansion:** Revisit governance when activity and responsibility justify shared maintainership; don't impersonate a community before it exists.

## Licensing decisions still required

**There is no LICENSE file yet.** The repository being public does not itself make the code open source. Before accepting substantive outside contributions, select:
1. A software license compatible with dependencies and the desired level of reciprocity.
2. A license policy for original narratives/documentation (potentially different from software).
3. A source-by-source rights/attribution policy for archival images, modern commentary, scans, recordings, translations and composition databases.
4. Whether formal contributor agreements are needed; default toward low-friction contributions where possible.

Do not copy external annotations or video scripts just because a PGN represents a public historical game.

## Review norms

- Source-backed corrections are welcome and should be attributable.
- Do not merge unreviewed AI-written material as verified history.
- Distinguish subjective editing preferences from objectively invalid chess or unsupported claims.
- Publish accessible content and avoid adversarial difficulty gatekeeping.
- Protect maintainers' time; allow asynchronous, scoped contributions with clear review expectations.

Before community promotion, add a chosen license, code of conduct with reporting contact, and contribution checks. See [Open Source Guides](https://opensource.guide/).

## Sustainability and incentives

No growth or monetization target is required. If money, hosting, patronage, or partnerships later become relevant, evaluate them against reader freedom, author credit, contributor voice, maintenance capacity, and public availability. The business model must follow demonstrated usefulness, not dictate the reading experience.
